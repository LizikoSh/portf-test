# Адмінка для portfolio-liziko.vercel.app — спрощений варіант (Pages CMS)

Це **не самописний бекенд**. Сайт залишився статичним HTML/CSS/JS на Vercel. Редагування відбувається через готовий Pages CMS, який записує зміни до GitHub. База Supabase, окремий сервер, пароль на сайті й токени не потрібні.

## Підключення — один раз

1. **Збережи резервну копію** поточного сайту / GitHub-репозиторію.
2. У GitHub Desktop створи гілку `pagescms-test` від `main` або зроби окремий тестовий репозиторій. *Не замінюй робочий `main`, поки не перевіриш результат.*
3. Скопіюй усі файли цього архіву до папки вибраної гілки/репозиторію. **Важливо:** файл `.pages.yml` прихований (назва починається з крапки); переконайся, що він теж скопійований до кореня поруч з `index.html`.
4. У GitHub Desktop натисни **Commit** → **Publish branch** (або **Push origin**). Vercel створить Preview-збірку для гілки, якщо вже підключений до репозиторію. Якщо потрібна окрема копія сайту, під’єднай тестовий репозиторій у Vercel як новий проєкт із **Framework = Other**, коренем `./` і без команди збірки.
5. Відкрий **https://app.pagescms.org/**, увійди через GitHub і дозволь застосунку доступ *лише до обраного репозиторію* (або за власним вибором). Обери цей репозиторій та гілку, де знаходиться `.pages.yml`.
6. У меню відкрий **«Галереї та роботи»** або потрібну сторінку. Зміни назву картки, натисни **Save**. Зміна створить коміт у відповідній гілці GitHub. Vercel автоматично зробить нове розгортання. Онови сторінку після завершення розгортання.
7. Коли все перевіриш, об’єднай тестову гілку з `main` (якщо потрібно), але лише після перевірки.

**Адреса «адмінки»:** на сайті є сторінка `/admin/`, що пояснює та відкриває **https://app.pagescms.org/**. Сам редактор захищений входом GitHub, а не формою на сайті.

## Що можна редагувати

- **«Галереї та роботи»** → існуючі галереї (вебпроєкти, дизайн, AI-зображення, AI-відео): назви, описи, файли, посилання, показувати/приховати, додавати/видаляти/переставляти картки.
- Там само можна створити нову галерею: вкажи **унікальний код латиницею** (`branding`, `posters`, `ui-ux` тощо), її назву, тип (`image`, `video`, `web`) та додай роботи. Вона з’явиться в переліку напрямів на головній сторінці. Адреса галереї буде `gallery-collection.html?g=branding` (замість `branding` твій код).
- **Сторінки** → окремо редагуються всі зібрані видимі текстові фрагменти, URL посилань, основні зображення та SEO title/description. Для текстів збережено внутрішні ID, тому **ID не змінюй**. Підписи пояснюють, де текст знаходиться.
- **Медіа** → керування файлами в папках `images`, `images/video-previews`, `videos`. Зображення/відео можна вибрати або завантажити безпосередньо в полі картки. Для відео можна завантажити обкладинку.

### Як додати роботу

1. «Галереї та роботи» → потрібна галерея → «Роботи» → додати елемент.
2. Заповни назву, завантаж **зображення** (для галереї `image` або `web`) чи **відео** (для `video`). Посилання на зовнішній файл можна вказати окремим URL, якщо файлу в репозиторії немає.
3. Для вебпроєкту додай опис і URL сайту; для відео — обкладинку.
4. «Показувати роботу» = увімкнено. Перетягни картку у потрібне місце списку (якщо інтерфейс Pages CMS підтримує перестановку в поточній версії), збережи. Для тимчасового приховування вимкни перемикач.

### Важливо знати

- **Чернеток немає.** Збереження в CMS одразу записується у вибрану гілку GitHub. Якщо редактор працює з `main`, після деплою це змінить живий сайт. Для проб використовуй тестову гілку.
- **Контент на сторінках завантажується з JSON у браузері.** В HTML залишено базові значення як запасний варіант. SEO заголовки й описи змінюються скриптом у браузері; пошукові роботи не завжди використовують їх так само, як статичний HTML. Якщо для тебе важлива SEO-індексація *нових* текстів, пізніше варто додати збірку зі статичним вбудовуванням контенту.
- GitHub обмежує розмір **одного файлу до 100 МБ** для звичайних комітів; великі відео краще зберігати окремо та вставляти публічне посилання. Доступний ліміт завантаження у Pages CMS може бути меншим.
- Сторінки `gallery-images-1.html`, `gallery-video1.html`, `gallery-video-2.html` в оригіналі — дублікати/варіанти. Вони відображають ті ж масиви робіт, що й відповідні основні галереї, але тексти їхніх сторінок редагуються окремо.
- В архіві вихідного сайту існують лише `images/liziko-smm-site-001.webp` … `004.webp`. Неіснуючі зображення `005` … `020` **не внесені** до керованого каталогу.
- **Дизайн CSS не перероблявся.** Зміни вносилися до HTML для позначення редагованих фрагментів, у JSON і JS для підключення CMS.
- Щоб скасувати невдале збереження, можна відкотити коміт у GitHub.

## Ключові файли

| Файл | Призначення |
|---|---|
| `.pages.yml` | Налаштування Pages CMS (в корені репозиторію) |
| `content/galleries.json` | Галереї, картки й видимість |
| `content/pages/*.json` | Тексти, посилання, основні зображення, SEO |
| `assets/js/portfolio-content.js` | Відображення даних CMS на сайті |
| `admin/index.html` | Посилання на зовнішній редактор |
| `gallery-collection.html` | Шаблон нових галерей |

## Самоперевірка

Після запуску перевір: головну сторінку; усі чотири галереї; відкриття збільшених зображень; запуск відео; URL вебпроєктів; редагування підпису через Pages CMS; додавання нової роботи; приховування картки; нову галерею; мобільне відображення.

Офіційна документація: https://pagescms.org/docs/quick-start/ та https://pagescms.org/docs/configuration/
